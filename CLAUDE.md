# Counterpart — working notes for Claude

HR26 Agnes hackathon, problem HR26-AI-02 (Marketing Campaigns). Product: an agentic "marketing employee" for any small business. Owners sign up, onboard their business (items and prices, languages, website), and run campaigns. `kaapi-kone` (a Jayanagar café) is the seeded DEMO business (`is_demo`), reachable only through "Try the demo". The pitch is that the SYSTEM (locked facts, guard, attribution, experiments, ledger) is the product; the LLM is a swappable component.

## Layout
- `supabase/migrations/` — the only schema source (14 tables, RLS on, offer_facts immutability trigger). Applied by `backend/scripts/migrate.py`.
- `backend/app/` — FastAPI modular monolith
  - `domain/` pure logic, no I/O: `facts.py` (slots + deterministic guard L1/L2), `audit.py` (L3 LLM check), `stats.py`, `economics.py`, `impact.py`
  - `services.py` — all DB business operations; used by BOTH the API and agent tools. Put rules here, not in prompts or routes.
  - `agent/` — `tools.py` (registry: args model, effect class, preconditions), `runtime.py` (policy gate + loop + inbox decisions), `situation.py` (snapshot + deterministic detectors), `prompts.py`
  - `providers/` — role-based `ModelRouter`; Agnes via `openai_compat.py`; `replay.py`; `ratelimit.py`
  - `api/owner.py` (owner routes, `require_owner`), `api/public.py` (QR landing, no auth)
- `backend/app/auth.py` — Supabase Auth over REST (sign in/up/refresh), `current_user` (verifies the Bearer token with GoTrue, 60 s cache), `require_member`/`business_for`. `api/workspace.py` — auth routes, `/me`, onboarding (`POST /businesses`, brand voice drafted by the model with a fallback), brand edits, photo library, `/agents`, `/results`.
- `backend/app/domain/culture.py` — hand-written festival knowledge (Dasara, Rajyotsava, Deepavali, Christmas, New Year, Sankranti, Ugadi, Ganesha, Eid, Holi): aliases in en/kn/hi, greetings and sayings (tested against the script guard), customs, angles, avoid list, dates for 2026-27 where confirmed. Used by the detector (built-in festival calendar), the agent snapshot (`festivals`), the writer prompt (`Culture` block when the campaign names a festival or runs during one), `GET /businesses/{slug}/culture` and campaign detail `culture`. Don't add greetings you can't verify.
- `backend/app/domain/analytics.py` — campaign funnel, daily/hourly series, breakdowns and deterministic optimisation tips (each may carry an `ask` sent to the agent). `POST /campaigns/{id}/simulate` (demo business only) adds labelled `source='simulated'` outcomes.
- `backend/app/sarvam.py` — optional Sarvam AI (`SARVAM_API_KEY`): `transcribe` (saaras:v4 speech to text, clips < 30 s; `POST /businesses/{slug}/speech`, composer records with MediaRecorder when `/me` features.sarvam, else the browser's speech API) and `translate`/`to_english` (mayura:v1). L3 audit and the fact wording check send every Kannada/Hindi text through it first and give the checker `independent_translation` (shown to the owner as the back-translation). Every caller works without a key.
- `backend/app/reviews.py` — reviews the owner brings in: own website (home + review/testimonial pages, JSON-LD Review) or pasted text. The model finds and labels (language, rating, sentiment, themes); `verified()` keeps only reviews found word for word in the source. Sources `website_review`, `pasted_review`. `POST /businesses/{slug}/reviews/import`. Never scrape Google/Zomato.
- Visit reviews (free, verified; migration `20261014000000`): once a personal code is redeemed, `/r/[code]` and `/c/[code]` (polling `GET /api/public/claims/{code}` via `lib/claim.ts`) show `ReviewForm`; `POST /api/public/claims/{code}/review` -> `reviews.submit_visit` (one per `claim_code`, `source='visit_review'`, campaign/asset kept) then `reviews.analyze` in the background (mood, themes, English via Sarvam or the model). WhatsApp claims: counter redeem triggers `whatsapp.ask_review` only inside the free 24 h window; a "1"-"5" answer becomes the review. Owner: Customers page summary, "Needs a reply" filter, `POST /reviews/{id}/reply/draft` (generation role, owner's voice, no offers), `PUT /reviews/{id}/reply` (can send on WhatsApp in-window), `PUT /businesses/{slug}/review-link` (Google "Ask for reviews" link shown to every reviewer: no review gating). Campaign analytics `ratings` per post.
- Coupons (`services.claim/counter_check/counter_redeem`, `domain/redeem.py`, migration `20261012000000`): "Get my code" makes a personal 7-letter code in `claims` (one per phone per campaign via a browser `device` id; the post's 6-letter touchpoint code still attributes it). The counter checks the locked facts deterministically (date_range, time_range `HH:MM-HH:MM`, weekday words; `condition` facts become a staff checklist), refuses used codes, and redeems outside the rules only with a reason. Optional `bill_amount` -> `outcome_events.meta` -> ₹ sales in results/analytics. Staff phones: owner sets a counter PIN (`PUT /businesses/{slug}/counter`, scrypt, 5 tries then 15 min lock, new PIN clears `counter_sessions`); public `/k/[code]` (customer QR) and `/k/desk/[slug]` use `/api/public/counter/*` with the token in the body (the proxy forwards no custom headers). `profile.whatsapp` adds a wa.me claim button.
- Auto-publish: locking with `?autopublish=true` (default in the UI) or `PUT /campaigns/{id}/autopublish` sets `campaigns.autopublish_version`; `services.autopublish` (called at the end of `generate_copy` and `validate_assets`) publishes posts approvable against that facts version (picture-led ones need their picture). A new offer version asks again.
- `backend/app/autofill.py` — sign-up from one link (`POST /onboarding/read-link`): website pages (menu/about/contact) or a Google Maps link (Places API when `GOOGLE_MAPS_API_KEY`, else the name in the URL). `checked()` keeps only names/places/prices found in the page text; only Indian mobiles prefill WhatsApp. The onboarding page opens on this, then shows every field on one review page.
- `backend/app/channels/` (docs/CHANNELS.md; `scripts.go_live` connects both in one run: checks values with Meta, 60-day WhatsApp token, finds the WABA, cloudflared quick tunnel -> PUBLIC_BASE_URL, registers the webhook via `/{app}/subscriptions` + WABA `subscribed_apps` override, writes `channel_accounts`): `meta.graph` is the only Graph API caller (tests replace it). `whatsapp.py`: per-business Cloud API number in `channel_accounts`; signed webhook `GET/POST /api/public/whatsapp/webhook` (Next proxy forwards `x-hub-signature-256`); a customer message containing a post code gets a personal claim code back (free reply in the 24 h window), receipts update `channel_messages`, STOP/START opt out/in (`wa_contacts`); `broadcast` sends a live post (free in window, approved template otherwise) with a `?m=` ref per message. `instagram.py`: Instagram API with Instagram Login (graph.instagram.com, v25.0): publish (browser-rendered JPEG, uploaded to Supabase Storage for a public https URL), link existing media, hourly insights (reach, likes, comments, saved, shares, views, total_interactions; engagement = interactions/reach). Comments as reviews (migration `20261015000000`: `external_id`, `author`, `category`): `instagram.sync_comments` (latest 25 posts, skips the business's own comments, at most hourly via an atomic `channel_accounts.meta.comments_at` claim; Customers page load and `POST /instagram/sync`) stores `source='instagram_comment'`, then `reviews.read_comments` sorts them in batches of 40 per model call (praise/complaint/question/suggestion/mention/spam + mood, topics, language, English). Spam is hidden from the owner's lists and language mix. Questions and complaints count as "Needs a reply"; `PUT /reviews/{id}/reply` with `send_instagram` posts a public reply under the comment. Campaign analytics returns `channels`. Customer code page `/c/[code]`.
- Analytics honesty: opens count once per phone (`device` on visit); comparison tips need ≥90% posterior probability (`analytics.SURE`); breakdowns carry a 90% `likely` range; the demo simulation stays inside the campaign's dates and offer rules and replaces earlier simulated rows.
- `backend/app/photos.py` — photos of the business itself: website import (SSRF-guarded: public hosts, ports 80/443, size caps), Google Places API (New) photos with attribution, uploads; the `vision` role captions them in batches; `choose()` matches a post to a photo deterministically (penalises reuse within a campaign).
- `frontend/` — Next.js 15 App Router. Owner pages live in the `app/(app)` route group, wrapped by `BusinessProvider` (`lib/business.tsx`: `/me`, selected business in localStorage). `/login`, `/signup`, `/onboarding`, `/r/[code]` sit outside it. `app/api/[...path]/route.ts` proxies to the backend, attaches the access token from the httpOnly `cp_at` cookie and refreshes once on 401 (`cp_rt`). `app/api/session/[action]` signs in/up/out and sets cookies. `middleware.ts` sends owner pages without a session to /login. `lib/api.ts` has `api()`, `useResource()` (refetch on ledger SSE), `useLedgerEvents()` and `setLiveBusiness()`.
- `data/seed/kaapi_kone.json` — synthetic demo data; `demo_new_reviews` is the on-stage batch that triggers the complaint-spike detector.

## Invariants (do not weaken)
- Model output never contains offer values; only `{{fact_key}}` slots. L1 blocks any digit authored outside slots (allowed_phrases in business profile are the only exception).
- Locked offer facts change only by locking a new version; DB trigger enforces it. Seed/reset purges use `set local counterpart.allow_purge = 'on'`.
- Facts drafts carry `wording_check` (reset on every save): deterministic script sanity + same numbers as English, then an LLM back-translation. Locking is refused while it is `failed` or missing; `unchecked` (no model) is allowed and shown.
- L2 `sounds_human` blocks machine-sounding copy (`AI_CLICHES`, long dashes, two '!') in the writer's text; owner edits only get a warning (`strict_voice`). The writer prompt lists the same phrases.
- L1 also blocks malformed Kannada/Devanagari letter sequences and Latin-inside-Indic words (`facts.malformed_words`). Built-in `BASELINE_FORBIDDEN` (en/kn/hi) applies on top of each campaign's list.
- `generate_copy` does one in-tool repair round with the guard's exact reasons. Story/poster limits count visible letters (`visible_len`).
- Owner decisions and direct locks resume the agent in the background (`resume`, default true; tests pass false).
- Tools with effect `customer_facing` or `fact` become inbox approvals unless `ctx.approved`.
- Asset approval requires validation passed against the CURRENT locked facts version and L3 not pending/failed (`services.approvable`).
- No LLM call inside an open DB transaction (read → call model → write).
- Every owner route depends on `current_user` and checks membership of the business it touches (unknown and forbidden both 404). New routes must do the same; tests override `current_user` (conftest `client.user["id"]`).
- Tokens never reach browser JS (httpOnly cookies set by the Next server). Secrets (Gemini, Agnes, Supabase secret key, Google Maps key, owner token, demo password) only in `backend/.env` / server-side env. Set them with `scripts.set_secret` (hidden prompt, tested), never through chat.
- Posts use real photos of the business first; AI pictures are only a fallback (`AI_PICTURE_FALLBACK`) and are always labelled. Never scrape Google Search/Images; Google photos come only from the Places API with attribution.
- Demo-only actions (synthetic review batch) refuse non-demo businesses.
- Synthetic/replayed data is always labelled in the UI.

## Design system (frontend)
Tokens in `frontend/app/globals.css` ("the counter book", replaced the green "Forest" look on 2026-10-09 because it read as generic AI). Three inks with one job each: ink black (owner's words, primary actions, headlines), pen blue `pen` (Counterpart's work: what agents wrote/checked/found, links), highlighter `marker` yellow (what needs the owner now: next step, approvals). `kumkum` red = problems and the live dot only; `turmeric` = warnings. Paper `#f3f2ed`, flat `.night` ink surface for the few dark blocks. Fonts: Anek Latin/Kannada/Devanagari (one family; headings `font-stretch` 80% signboard style, `.sign` for big numbers) + Martian Mono (codes, work log). Shapes square-ish (4/6/8/10px radius tokens), hairline/ink rules instead of floating cards, almost no shadows. Helpers: `.hl` highlighter, `.ruled` + `.margin-rule` notepad, `.stamp` rubber stamp, `<Stamp>`. Custom classes live in `@layer components` so Tailwind utilities (e.g. `hidden`) win.
Flow: every campaign is Brief, Offer, Posts, Share, Results (`lib/journey.ts`: `stepOfSummary`, `stepOfDetail`, `nextAction`). Today = what needs you (yellow) + notepad composer + campaign ledger (`CampaignLedger` rows with `JourneyMini`). Campaign page = `JourneyTrack` + "Next" line + numbered sections #offer #posts #share #results; Share (`components/share-panel.tsx`) gives each live post its link, WhatsApp message (wa.me), caption, QR. Nav groups work (Today/Campaigns/Results) and business (Photos/Brand/Customers); Counter and AI team are buttons. Campaigns page is a metrics table (live, opened, claimed, redeemed, conversion, working best) with filters. Per-business themes: `lib/theme.ts` (8 themes, auto from brand palette/kind/voice or `dna.theme`), applied by `BusinessProvider` as CSS vars incl. `--color-brand` used on posts. Watermark: `dna.watermark` (default on) via `PostStyle` context, drawn in `previews.tsx`. Post editor: `components/post-editor.tsx` (portal; overlays inside animated cards must use `createPortal`). Work log is a per-browser toggle (`lib/worklog.ts`, off by default) that opens a right-hand drawer from `Shell` at every width. Brand palette words resolve to real colours in `lib/colors.ts` (owner picks stored in `dna.palette_hex`); auto theme = `brandTheme()` built from those colours (contrast-checked), else a keyword theme. Campaign page: Performance first once live (`components/campaign-analytics.tsx` over `GET /campaigns/{id}/analytics`), Festival notes (`components/festival-card.tsx`), then offer, posts, share, A/B. Min text size 12 to 13px; headings `font-stretch` 90%. Pitch: `docs/PITCH.md`. Icons: Phosphor only. Set `lang` on customer copy. No em/en dashes in UI copy.

## Models (2026-10-09)
- Backups (`providers/__init__.py`): each role chain is expanded to Gemini models, then the same models on `GEMINI_API_KEY_2` (`name@2`, a different Google project = its own quota), then Groq and Cerebras (free, no card; Cerebras first for the checker so writer and checker differ), then Agnes. Strict providers get plain messages (`_plain` drops Gemini's extra_content). A 429 with retry-after > 30 s fails over and rests the model.
- Gemini (OpenAI-compatible endpoint, `GEMINI_API_KEY`) is the default text provider; each id in `GEMINI_MODELS` is a provider name used in `ROLE_*` chains. Writer and checker start on different models. Agnes = images + last fallback.
- Gemini free tier: ~20 requests/day PER MODEL, no image quota, Pro models 0. 503 "high demand" is common; 503 and quota 429 fail over immediately (`openai_compat._raise_for`). Gemini 3 needs thought signatures echoed back: runtime re-sends the raw assistant message.
- Posts = model headline + body only; the offer box (`rendered.offer`, required facts' locked wording) and CTA (`CTA_TEXT`) are system-rendered. PNG export happens in the browser (html-to-image) because server Pillow lacks raqm for Kannada shaping.

## Agnes behaviour seen live (2026-10-09)
- Sends object/array tool arguments as JSON strings (runtime decodes on validation failure).
- Sometimes announces the next step in prose and stops (runtime nudges once).
- Kannada output is unreliable (invented words, wrong meaning such as "night" for pm, "cancellation" for off) and its own back-translation check is lenient. The guard catches much of it; how to get correct Kannada is an open team decision.
- Playwright plugin needs Google Chrome (not installed). Use the cached Chromium: `uv run --no-project --with playwright==1.63.0 python script.py`.

## Agnes API facts (checked 2026-10-08)
- Base `https://apihub.agnes-ai.com/v1`; chat is OpenAI-compatible with `tools`; no JSON mode (use `router.chat_json`).
- Images: `size` "1K"/"2K", `ratio` e.g. "3:4"; `response_format` goes inside `extra_body`; reference images in `extra_body.image` (URLs or data URIs).
- Free plan: text 10 RPM, image 1K 10 RPM, video 1 RPM.
